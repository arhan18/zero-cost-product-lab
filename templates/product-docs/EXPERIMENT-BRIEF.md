# Template — Experiment Brief

Copy to `research/ideas/<slug>/experiment-brief.md` for Experiment Track runs (NOT a PRD — one page, decision-oriented). Every claim tagged FACT / INFERENCE / HYPOTHESIS / UNKNOWN with sources where public.

## 1. Problem
One paragraph: who hurts, how, how often — with the strongest evidence link.

## 2. Target user
Narrow: role, context, where reachable $0. Never bare "small businesses."

## 3. One-sentence value proposition
The Gate-C sentence: helps [user] do [task] without [current pain].

## 4. Smallest useful version
The 1–3-day build: core workflow only, explicit exclusions list.

## 5. Why this is interesting
Signal class (PERSONAL PAIN / PUBLIC PAIN / WORKAROUND / EXISTING DEMAND / TREND / PRODUCT GAP / HYBRID) + why now.

## 6. Assumption under test
The single riskiest belief this experiment resolves (e.g. "solos will connect Gmail for this").

## 7. Cheap-build plan
Stack (defaults unless reasoned otherwise), data model sketch, what is deliberately NOT built, AI usage with per-operation cost + hard caps.

## 8. Launch channel
First channel + why these users are there + what "put in front of users" concretely means (post, listing, reply, deploy).

## 9. Success signals (predefined)
Observable thresholds: e.g. 5+ repeat users in 14 days; 3+ unprompted feature asks; 1+ pay intent. Likes/views explicitly excluded.

## 10. Kill signals (predefined)
Thresholds that end it: e.g. <20 visitors from 3 channels; zero repeat use; support burden >2 hrs/week; AI cost >$X with no pay path.

## 11. Budgets
Maximum time (days) + maximum money ($0 default; any spend needs human approval). Thresholds frozen before launch.
