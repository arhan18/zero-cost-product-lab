# Template — Product Requirements (PRD)

Used in **Phase 06**. Inputs: research + opportunity score. Must be readable by one developer in one pass.

## PRODUCT REQUIREMENTS

| Field | Value |
|---|---|
| Product slug | |
| One-sentence promise | helps [person] do [task] |
| Success metric (Phase 27 measures this) | |
| Date / owner | |

## 1. Users
The specific person(s) served; non-goal audiences.

## 2. The core task (happy path)
Numbered flow a new user takes; the one thing the product must do right.

## 3. Scope
- **In scope** (MVP): …
- **Explicit non-goals**: …

## 4. Edge cases & states
empty / loading / error / offline / repeat use / deleted inputs.

## 5. Pricing plan
- Model, price, payment provider (only fee-after-revenue per SYSTEM.md §25), payout timing.
- Mark the model `FACT`-validated or `HYPOTHESIS` to be tested.

## 6. Content & copy
Own words, tuned to the product (§14). No invented claims (§12).

## 7. Kill criteria planning
Point to the numbers that will be written into Scope Lock (Phase 07).
